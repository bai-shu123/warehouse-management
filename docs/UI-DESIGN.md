# 界面设计基线

## 1. 设计方向

这是一个每天重复使用的库存台账，不做营销型首页。界面把“可用数量、运输中的货、异常待办和最近操作”放在第一屏，像一张能快速核对的仓库工作台。

唯一的视觉记忆点是“运输轨道”：在两个库房之间用一条清晰的状态轨道表达发运、运输中、部分收货和完成。其余区域保持安静、紧凑，优先服务扫描和录入。

## 2. Token 草案

### 色彩

| Token | Hex | 用途 |
| --- | --- | --- |
| `--ink` | `#17242A` | 主文字、深色导航 |
| `--paper` | `#F5F7F4` | 页面底色，避免纯白刺眼 |
| `--panel` | `#FFFFFF` | 表格和表单底色 |
| `--teal` | `#176B6B` | 正常库存、主要操作 |
| `--ochre` | `#C98B2E` | 运输中、提醒 |
| `--coral` | `#C65A46` | 异常、危险回退 |
| `--line` | `#D6DEDA` | 分隔线和输入框边界 |

颜色同时配合文字和图标表达状态，不依赖颜色本身。回退使用珊瑚色危险区并与普通操作隔开。

### 字体

- 中文：`Noto Sans SC`，回退到系统无衬线字体。
- 俄语/哈萨克语：`IBM Plex Sans`，回退到系统无衬线字体。
- 数字：沿用正文字体，避免库存数字和业务字体之间跳动。
- 页面标题 28/34，模块标题 18/24，正文 14/22，表格数字 14/20。
- 不使用全大写标签，不使用负字距；长款号允许换行。

### 形状与间距

- 页面区域使用直角或 4px 圆角，重复卡片不做厚重阴影。
- 操作按钮高度至少 40px，触屏目标至少 44px。
- 8px 基础间距，桌面内容最大宽度 1440px，移动端左右边距 16px。
- 表格用细分隔线和固定列头，不把每一行包装成浮动卡片。

## 3. 桌面布局

```text
+----------------+------------------------------------------------------+
| 品牌 / 库房台账 | 顶栏：当前库房  时间  语言  用户                     |
|                +------------------------------------------------------+
| 总览           | 关键摘要：可用包数 | 件数 | 运输中 | 异常待办       |
| 我的库房       +-------------------------------+----------------------+
| 国内运输       | 运输轨道 / 待办                      | 最近操作           |
| 库房调拨       | 他人库房 ==运输中==> 自有库房      | 时间、操作人、数量 |
| 取货记录       +------------------------------------------------------+
| 款式           | 批次库存表：款号、日期、包数、件数、状态、操作      |
| 汇率与成本     |                                                      |
| 用户与权限     |                                                      |
+----------------+------------------------------------------------------+
```

左侧导航根据角色裁剪。管理员看到完整导航；员工只看到“我的库房、待收货、取货、我的记录”；财务看到“台账、统计、导出”。

## 4. 手机布局

- 顶部保留页面标题、语言切换和当前库房。
- 关键摘要改为横向滚动的数字带，不使用高度很大的统计卡片。
- 运输轨道变为纵向时间线，每个收货事件可展开。
- 表格转为可展开行：第一行显示款号、包数、状态，展开后显示件数、日期和备注。
- “确认收货”和“取货”是底部固定的主操作入口，打开全屏表单。
- 录入表单分为“数量”和“备注”两段，数字输入使用大号步进控件并支持直接键盘输入。

## 5. 核心页面与交互

### 总览

- 第一屏先显示可用库存、运输中和管理员待办。
- 可在“自有库房 / 两个库房”之间切换；员工只能看到自己的库房。
- 异常待办显示差异数量和下一步动作，点击进入处理页。

### 批次选择

- 取货表单先选款式，再显示可用批次列表。
- 批次行显示款号、入库日期、剩余包数、剩余件数；非管理员隐藏采购价。
- 支持多选批次，但每个批次的包数和件数都要单独填写。
- 数量超过余额时，在输入框旁即时显示“最多可取 X 包 / Y 件”，提交按钮保持禁用。

### 运输轨道

- 状态顺序固定为：待发运、运输中、部分收货、已完成、异常。
- 轨道上同时显示预计到达日期和实际收货事件。
- 目标库房员工只能看到与自己相关的运输和收货动作。
- 异常处理页把“继续等待、丢失、损坏、其他”作为明确的单选动作，提交前展示数量影响。

### 回退

- 普通记录详情页不显示危险按钮；管理员进入“更多操作”后才看到回退。
- 回退页先展示反向影响、关联批次和可能产生的负数，再输入原因。
- 第二步要求管理员重新输入密码/PIN；完成后显示回退编号。
- 已回退记录显示“撤销回退”，同样需要二次确认，不与普通保存按钮相邻。

## 6. 多语言体验

- 语言切换放在用户菜单，切换后立即更新界面，不改变当前表单数据。
- 关键术语固定映射，例如“包”“件”“运输中”“部分收货”“回退”。
- 俄语和哈萨克语较长文本允许自然换行，按钮不固定宽度到无法容纳长词。
- 日期、数字和货币格式按用户语言显示；数据库保存标准 ISO 日期和数值。

## 7. 无障碍与状态

- 所有图标按钮使用 Lucide 图标并提供可读的 tooltip/aria-label。
- 键盘焦点使用清晰的双层描边；错误不仅用红色，还提供文字说明。
- 加载、空数据、保存中、保存成功、权限不足和网络失败都有明确状态。
- `prefers-reduced-motion` 下关闭轨道动画，只保留状态变化。
- 离线或网络中断时禁止重复提交，并显示“尚未同步”的明确提示。

## 8. 设计评审结论

本方向刻意避开营销首页、渐变背景和统一圆角卡片，视觉重点落在服装库存的批次、数量和运输状态。暖色只用于提醒和异常，主界面仍以冷静的墨色、青绿色和浅灰为工作底色，适合高频台账操作。
